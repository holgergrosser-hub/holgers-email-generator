# Contributing to Holgers E-Mail Generator

Danke für dein Interesse am Projekt! 🎉

## 🚀 Getting Started

1. Fork das Repository
2. Clone deinen Fork: `git clone https://github.com/DEIN-USERNAME/holgers-email-generator.git`
3. Erstelle einen Branch: `git checkout -b feature/dein-feature`
4. Installiere Dependencies: `npm install`
5. Starte den Dev Server: `npm run dev`

## 📝 Code Guidelines

### JavaScript/React
- Verwende funktionale Komponenten mit Hooks
- Halte Komponenten klein und fokussiert
- Kommentiere komplexe Logik
- Nutze aussagekräftige Variablennamen

### CSS
- Nutze BEM-Notation wo sinnvoll
- Mobile-First Ansatz
- Keine inline-styles (außer für dynamische Werte)

### Commits
- Nutze aussagekräftige Commit-Messages
- Format: `type: description`
- Types: `feat`, `fix`, `docs`, `style`, `refactor`, `test`

Beispiele:
```
feat: add email template system
fix: resolve API key validation error
docs: update README with new features
```

## 🧪 Testing

Vor dem Pull Request:
1. Teste die App lokal: `npm run dev`
2. Baue das Projekt: `npm run build`
3. Teste den Build: `npm run preview`

## 🔄 Pull Request Process

1. **Update die README** falls nötig
2. **Teste deine Änderungen** gründlich
3. **Beschreibe deine Änderungen** im PR
4. **Verlinke relevante Issues**

### PR Template

```markdown
## Was ändert dieser PR?
[Beschreibung]

## Warum ist diese Änderung nötig?
[Grund]

## Wie wurde es getestet?
- [ ] Lokal getestet
- [ ] Build erfolgreich
- [ ] UI/UX überprüft

## Screenshots (falls UI-Änderungen)
[Screenshots hier einfügen]

## Checklist
- [ ] Code folgt den Style-Guidelines
- [ ] README aktualisiert (falls nötig)
- [ ] Selbst-Review durchgeführt
```

## 💡 Feature Requests

Hast du eine Idee? Öffne ein Issue mit:
- **Titel**: Klare Beschreibung
- **Beschreibung**: Was soll die Feature machen?
- **Warum**: Welches Problem löst es?
- **Wie**: Hast du Vorschläge zur Implementierung?

## 🐛 Bug Reports

Bug gefunden? Öffne ein Issue mit:
- **Titel**: Kurze Beschreibung des Problems
- **Schritte zur Reproduktion**: Wie kann man den Bug nachstellen?
- **Erwartetes Verhalten**: Was sollte passieren?
- **Tatsächliches Verhalten**: Was passiert stattdessen?
- **Screenshots**: Falls hilfreich
- **Browser/OS**: Welche Umgebung?

## 📚 Dokumentation

Dokumentation ist wichtig! Bei Änderungen:
- Aktualisiere die README
- Füge Code-Kommentare hinzu
- Erstelle Beispiele wenn nötig

## 🎨 Design Guidelines

- **Einfachheit**: Keep it simple
- **Konsistenz**: Folge dem bestehenden Design
- **Zugänglichkeit**: Denke an alle Nutzer
- **Performance**: Optimiere für Geschwindigkeit

## 🤔 Fragen?

Bei Fragen:
- Öffne ein Issue mit dem Label `question`
- Kontaktiere @holger (per E-Mail oder LinkedIn)

## 📜 Code of Conduct

Sei respektvoll und konstruktiv. Wir wollen eine freundliche Community!
